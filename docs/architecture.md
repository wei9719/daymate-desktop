# 技术架构

## 目标

DayMate 的核心不是“采集越多越好”，而是在最小采集范围内回答三个问题：昨天主要做了什么、今天先做什么、怎样更容易开始。

## 分层

1. `src/App.tsx`：页面组合与用户交互，不直接访问 Windows API。
2. `src/store.ts`：任务、偏好和本地规则；`selectNextTask` 可独立测试。
3. `src/native.ts`：前端唯一桌面桥接层；浏览器预览会安全回退为空数据。
4. `src-tauri/src/lib.rs`：系统采集、SQLite、Tauri 命令和托盘。
5. `src-tauri/src/ai.rs`：AI 地址/输出验证、后台 HTTP、每日调用预算、在途请求限制和内存缓存。
6. `src-tauri/src/system.rs`：真实开机启动状态、数据目录启动参数、系统通知状态和固定文案通知。
7. `src-tauri/src/database.rs`：数据库版本检查、事务迁移与损坏结构保护。
8. `src/services/persistedState.ts`：逐字段恢复任务和偏好，兼容旧数据与损坏记录备份。

## 双窗口陪伴模式

DayMate 使用两个共享同一套 React 资源的 Tauri 窗口：`main` 承载完整界面，`companion` 是透明、置顶且不显示在任务栏中的桌面浮动球。主窗口隐藏时显示浮动球，点击浮动球后恢复主窗口；浮动球偏好继续由同源的 Zustand 本地存储管理。

权限分离针对原生桥接能力，不是浏览器存储或操作系统进程级隔离：两个同源窗口仍可访问共享的 WebView 任务/偏好存储。API Key 不在该存储中，活动 SQLite 也只能通过授权给主窗口的命令访问。

## 活动数据流

```text
每 3 秒采样前台窗口
  → 获取进程名和可执行文件路径
  → 可选获取窗口标题
  → 检查空闲是否达到 5 分钟
  → 应用切换 / 跨天 / 60 秒时刷新会话
  → SQLite WAL 批量写入
  → get_today_stats 按应用聚合查询并缓存本机程序图标
  → React 时间回顾页绘制排行图、占比图和应用明细
```

DayMate 自身不计入有效应用时长。窗口标题只有用户主动开启后才进入内存和数据库。

使用单调时钟计算采样时长，并与 UTC 时间轴核对；休眠和调时后的不确定区间不计入应用时长。午夜区间按两侧秒数切分，键鼠次数按观察时刻归属，不保存单次输入时间。暂停/删除/读取快照与采样共用短期锁，图标提取在锁外执行。恢复记录后的首个不完整区间丢弃，避免计入关闭期间的输入。它仍是约 3 秒采样的近似统计，不是精确工时计费或审计工具。

## 数据表

- `migration_history`：数据库结构版本和应用时间。
- `app_usage_sessions`：应用名、可执行文件路径、可选标题、开始/结束、活跃/空闲秒数和键鼠次数。
- `ai_daily_usage`：本地日期主键和请求次数；v5 迁移新增，不包含密钥或模型消息。

查询按开始时间和应用名称建索引。数据库采用 WAL，采样不会每三秒直接写盘。

迁移先检查最高版本，拒绝修改新于当前应用的数据库；升级在单一事务内提交，失败回滚结构和版本记录。v0.7.0 沿用 v5，不增加表；各服务商的地址和模型档案通过偏好逐字段兼容恢复。

## 本地规则

“帮我选一件”依次比较：截止日期、优先级、预计用时。已完成任务永不参与选择；没有 AI Key 时功能完整可用。

## 后续演进

- 把任务和偏好从 WebView 本地存储迁移到 SQLite，并提供一次性迁移。
- 增加按日/周查询和应用分类表。
- 增加任务和专注历史的统一持久化，验证跨窗口状态同步。

## AI 与权限

AI 从显式发送预览进入原生异步命令，耗时 HTTP 在工作线程完成。Rust 统一检查 URL、模型、参数与输出；使用有限类别 JSON，返回文本仅作为文案。原生层限制同时一个请求，每次实际发送前写入每日预算，支持 15 分钟内存缓存。超时不自动重复请求；详细决策与官方参考见 [AI 工程复查](ai-development-review.md)。

v0.7.0 增加模型目录与独立鼓励命令，同样只授权主窗口。目录在验证原聊天接口密钥绑定后，推导同根 `/models`，限制响应 256 KiB、最多 300 个标识符，并缓存 10 分钟；硅基流动官方根使用 `sub_type=chat`，显式声明输出模态的图片模型不会进入聊天目录。每类缓存都参与密钥变更失效保护。

音乐上下文增加有限枚举的场景、心情以及小时，独立鼓励只使用这些字段和语气；模型结果不能产生 URL 或程序动作。前端保留长期音乐偏好，将 AI 选择作为临时播放类别，并用请求版本和当前配置快照丢弃过期结果。各服务商的普通连接档案独立存储，不保存或导出密钥。

协议兼容不等于模型行为一致：仅硅基流动官方根的已确认 Qwen3 型号使用非思考参数；仅商汤官方根的 SenseNova 6.8 使用 2000 输出预算和 60 秒超时，以容纳其默认推理。截断和没有正文均不作为成功。具体配置、费用与图片能力边界见 [AI 配置指南](ai-setup.md)。

密钥只在 Windows 凭据管理器；远程 AI 调用不经过 WebView。界面 CSP 限制脚本为本地资源；音乐检索仅连接 Audius，HTTPS 音频流支持其分布式节点和本地导入的 blob URL。

新凭据用带版本的结构保存服务商、规范化最终接口地址和密钥，改变协议/主机/端口/路径不会复用原密钥。旧官方地址凭据保持兼容；旧自定义地址需重新保存。AppManifest 列出全部原生命令并显式授权，主窗口和浮球使用分离的 capabilities；没有远程页面授权。音乐响应先校验结构和大小，再由可信曲目 ID 构造官方播放入口，不接受任意流地址。

自启通过 Tauri 官方插件注册/撤销，启动参数携带数据目录，避免重新登录后换用另一份活动数据库。通知发送固定文案并检查 Windows 状态，前端只有用户允许时才发送专注完成通知。
