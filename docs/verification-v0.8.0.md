# v0.8.0 验证记录

日期：2026-09-12。此文件记录本轮真实检查，不把模拟测试、HTTP 200、目录结果或合成评测等同于真实使用效果。最终发布门禁以同版本 GitHub Actions 为准。

## 测试隔离

- 本机仅检查源码、运行单测/构建和独立接口诊断，不启动、安装、更新或操控本机旧 DayMate。
- 项目、依赖缓存、测试临时数据库与下载产物保留在 D 盘工作目录。
- 浏览器交互和安装测试只在 GitHub 托管 runner 上执行，使用虚构偏好、模拟曲库和独立数据目录，不放入维护者 Key。
- 真实接口读取已授权的本机服务商凭据，只访问对应官方地址；不向智谱转发硅基流动 Key，不读取真实任务或活动明细。

## 音乐接口与合成评测

三次真实 Audius 目录请求均返回 HTTP 200：

| 查询                             | 有效返回 | 观察                                                  |
| -------------------------------- | -------- | ----------------------------------------------------- |
| ambient + Peaceful / Easygoing   | 40       | 37 条 Peaceful、3 条 Easygoing，约 3.5 秒             |
| electronic + Upbeat / Energizing | 40       | 12 条 Upbeat、28 条 Energizing，约 2.2 秒             |
| guzheng                          | 40       | 标签分布多样，约 2.0 秒；不能据此声称全部都是中文歌曲 |

`mood` 使用官方 REST OpenAPI 的重复查询参数。这里只确认目录、过滤参数与返回字段，没有下载远程音频，没有证明全部候选在任意地区/网络可播。参考 [Audius 官方接口](https://docs.audius.co/sdk/tracks/)。

固定评测为 `synthetic-mood-v1`：12 个手写场景、12 首虚构元数据、Top-5，算法 `mood-feedback-v1`。同一组数据上的标签命中比例：旧日期轮换基线 0.35，本版 0.75；候选覆盖 10/12。它是开发者合成规则回归，不是用户满意度、真实推荐准确率、临床效果或独立论文复现。

还覆盖显式搜索不被心情挤掉、近期歌曲仍可搜索、不喜欢硬排除、未知作者不被错误归因、缓存、超时与离线回退。

## 实际 AI 请求

### 商汤 SenseNova

通过独立脚本向官方 `sensenova-6.8-flash-lite` 发起一次固定中文鼓励测试，使用现有 2000 输出预算与 60 秒超时；不自动重试。本次 HTTP 200，但响应只有推理字段、没有可用正文，且 `finish_reason` 表示输出预算用尽。因此判定 **生成未通过**，不展示推理文本，不报告连接成功。

官方指南说明预算包含推理内容；本轮不盲目提高预算、修改用户已存模型或发送未核验的思考开关。可选择账号可用的短回答模型，再显式测试。没有执行图片生成。参考 [SenseNova 官方 API 指南](https://github.com/OpenSenseNova/SenseNova6.8/blob/main/API.md)。

### 硅基流动通义千问

独立 live 用例使用 `Qwen/Qwen3-8B`，最多六次请求：模型目录、连接、三组场景/心情/意图和独立鼓励。默认单测与 CI 跳过此用例；它验证真实 API 与受控输出契约，不验证主观音乐效果。最终结果在本轮完成后记录于下方验收状态。

本轮实际执行中模型目录与连接检查通过，后续结构化音乐请求超时，live 套件因此中止并报告失败，未完成全部三场景及鼓励验收。另发一次独立固定鼓励诊断返回 HTTP 500；不无限重试、不把这些错误写成“AI 已全面验证”。自动回退与静态错误信息由本地假服务/组件回归验证，服务商恢复后仍需显式复测真实内容。

已完成的原生检查：51 项 Rust 测试通过、1 项真实 Key 测试默认跳过；fmt 与 Clippy 通过。发布/审计/SARIF 脚本 21 项通过。最初一次本地并发编译因系统内存不足终止，限制 `CARGO_BUILD_JOBS=1` 后重跑通过，没有修改测试来掩盖资源问题。npm 10 在生成新依赖树时内部异常，使用 D 盘隔离的 npm 11.6.2 生成兼容 v3 锁文件，不替换全局工具、不降低依赖校验。

前端完整回归：22 个文件、233 项测试通过（Vitest 4.1.11，单 worker），包含新播放器竞态、反馈、精确搜索与专注/日期用例；生产构建通过。所有源码格式、ESLint、TypeScript 与版本一致性检查通过。npm 官方全依赖审计为 348 个依赖、0 项漏洞；源码敏感凭据模式扫描无命中，93 个 Markdown 内部链接有效。Playwright 测试发现为 2 个文件、5 条流程，实际执行交由云端。
